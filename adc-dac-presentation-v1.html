Why convert?

โลกจริงเป็น อนาล็อก แต่ MCU เข้าใจแค่ 0 กับ 1

  • อนาล็อก — ต่อเนื่องทั้ง เวลา และ ค่า เช่น อุณหภูมิ เสียง แสง ความชื้น แรงดันจากเซ็นเซอร์
  • ดิจิทัล — ค่า เป็นขั้น และ เป็นช่วงเวลา เก็บเป็นเลขฐานสอง ประมวลผล เก็บ ส่ง และรันโมเดล AI ได้
  • ADC พาข้อมูลจากโลกจริง เข้าระบบดิจิทัล
  • DAC พาผลลัพธ์ ออกไปสั่งลำโพง มอเตอร์ หลอดไฟ
อนาล็อก (ต่อเนื่อง)ดิจิทัล (สุ่ม + ปัดเป็นระดับ)

How ADC works · Lab 1

ADC ทำงาน 3 ขั้นตอน

1Sampling

สุ่มอ่านค่าแรงดันเป็นช่วงเวลาเท่า ๆ กัน (อัตรา fs)

2Quantization

ปัดค่าที่อ่านได้ให้เป็น ระดับ ที่ใกล้ที่สุด (จำนวนระดับ = 2N)

3Encoding

แปลงระดับเป็น เลขฐานสอง N บิต ส่งให้ MCU

สัญญาณจริงจุดที่สุ่มค่าหลังปัดเป็นระดับ

สิ่งที่ MCU ได้รับ (8 ตัวอย่างแรก)

Sampling · Lab 2

Nyquist: ต้องสุ่ม เร็วกว่า 2 เท่า ของความถี่สูงสุด

fs > 2 · fmax   |   falias = | f − k·fs |   (k = จำนวนเต็มที่ใกล้ที่สุด)
สัญญาณจริงจุดที่ ADC สุ่มได้สัญญาณที่ MCU "เห็น" (alias)

ทางแก้ในงานจริง: ใส่ Anti-aliasing low-pass filter ก่อนเข้า ADC เพื่อตัดความถี่เกิน fs/2 ทิ้ง

Resolution · Lab 3

จำนวนบิต = ความละเอียด

8ระดับ = 2N
412 mV1 LSB = Vref / 2N
±206 mVerror สูงสุด = ±½ LSB
19.8 dBSQNR ≈ 6.02N + 1.76
LSB = Vref / 2N

เพิ่มทุก 1 บิต → ระดับเพิ่ม 2 เท่า, LSB เล็กลงครึ่งหนึ่ง, SQNR ดีขึ้น ≈ 6 dB (ค่าสูงสุดในอุดมคติ — ของจริงต่ำกว่าเพราะ noise)

Architectures

ADC มีหลายแบบ — แลกกันระหว่าง เร็ว · ละเอียด · ประหยัด

ชนิดหลักการความเร็วความละเอียดจุดเด่น / จุดด้อยใช้ในงาน
Flashตัวเปรียบเทียบ 2N−1 ตัว ตัดสินพร้อมกัน ใช้ 1 รอบเร็วที่สุดต่ำ (~6–8 บิต)เร็วมาก แต่กินไฟ/พื้นที่ชิปมากออสซิลโลสโคป, วิดีโอ, สื่อสารความเร็วสูง
SAR ★ค้นหาแบบทวิภาค (binary search) ใช้ N รอบ ต่อ N บิต — มี DAC อยู่ข้างในปานกลาง (kSPS–MSPS)ปานกลาง–สูง (8–18 บิต)วงจรง่าย ประหยัดไฟ ไม่มี latency สลับช่องได้ดีADC ใน MCU ส่วนใหญ่ (ESP32, Arduino), data logger
Sigma-Delta (ΣΔ)สุ่มเร็วมาก (oversampling) 1 บิต แล้วใช้ digital filter รวมเป็นค่าละเอียดช้าสูงมาก (16–24+ บิต)แม่นยำสูง แต่ไม่เหมาะสัญญาณเร็วเครื่องชั่ง (เช่น HX711), เซ็นเซอร์แม่นยำ, เครื่องมือแพทย์, เสียง
Pipelineแบ่งเป็นหลายสเตจต่อกัน แต่ละสเตจแปลงไม่กี่บิตแล้วส่งส่วนที่เหลือต่อเร็ว (> 5 MSPS ขึ้นไป)ปานกลาง (8–16 บิต)สมดุลระหว่าง Flash กับ SAR แต่มี latencyกล้อง/วิดีโอ, อัลตราซาวด์, วิทยุ

ช่วงตัวเลขเป็นค่าโดยประมาณจากเอกสารผู้ผลิตชิป (Analog Devices) — แต่ละสถาปัตยกรรมมีสเปกที่ทับซ้อนกันได้ การเลือกขึ้นกับงานเป็นหลัก

DAC

DAC: แปลง ตัวเลข → แรงดัน

Vout = Vref × D / 2N   (เช่น 3.3 V × 128 / 256 = 1.65 V)

R-2R Ladder

ใช้ตัวต้านทานแค่ 2 ค่า (R กับ 2R) ต่อเป็นบันได แต่ละบิตแบ่งแรงดันเหลือครึ่งหนึ่ง — แม่นง่าย พบในชิป DAC ทั่วไป

Binary-weighted

ตัวต้านทานค่าต่างกันตามน้ำหนักบิต (R, 2R, 4R…) เข้าใจง่าย แต่ถ้าบิตเยอะต้องใช้ค่าที่แม่นมาก

PWM + RC filter

ไม่มี DAC บนชิปก็ทำได้: ส่ง PWM แล้วผ่านตัวกรอง low-pass ได้แรงดันเฉลี่ย ∝ duty cycle — ใช้ได้กับทุกบอร์ด

Sigma-Delta DAC

ส่งสตรีม 1 บิตความเร็วสูง แล้วกรองเป็นอนาล็อก นิยมในงานเสียงคุณภาพสูง

เอาต์พุตของ DAC เป็น ขั้นบันได (ค่าคงที่ระหว่างตัวอย่าง) → ต้องมี reconstruction filter (low-pass) ทำให้เรียบ — ลองดูในสไลด์ถัดไป

แรงดันอินพุต0–5 V0 ถึงประมาณ 3.3 V (ขึ้นกับ attenuation)

// ESP32 (Arduino core) — อ่าน ADC1 (ใช้ร่วม Wi-Fi ได้)
const int PIN = 34;          // ADC1

void setup() {
  Serial.begin(115200);
  analogReadResolution(12);       // 12 บิต
  analogSetAttenuation(ADC_11db); // ช่วงอินพุตกว้างสุด
}
void loop() {
  int raw = analogRead(PIN);        // 0–4095
  int mV  = analogReadMilliVolts(PIN); // calibrate แล้ว
  Serial.printf("%d  %d mV\n", raw, mV);
  dacWrite(25, 128);  // DAC ≈ 1.65 V
  delay(100);
}

dacWrite() ใช้ได้เฉพาะชิปที่มี DAC (ESP32 ดั้งเดิม) · ESP32-S3 ไม่มี DAC ในตัว → ใช้ PWM + RC หรือ DAC ภายนอก (ตรวจ datasheet ของบอร์ดที่ได้รับแจกก่อนใช้งาน)

Real-world pitfalls

ปัญหาที่ เจอจริง และวิธีแก้

ค่าอ่านกระโดด (Noise)

ADC บน ESP32 ไวต่อ noise → ต่อ ตัวเก็บประจุ 0.1 µF ที่ขาอินพุต และ multisampling (อ่านหลายครั้งแล้วเฉลี่ย)

Aliasing

มีความถี่สูงปนมาเกิน fs/2 → ใส่ RC low-pass filter ก่อนเข้า ADC และเลือก fs ให้เหมาะกับสัญญาณ

Vref ไม่ตรง / ไม่เป็นเส้นตรง

Vref ภายในของ ESP32 แต่ละตัวต่างกันได้ ~1000–1200 mV → ใช้ analogReadMilliVolts() หรือ esp_adc_cal เพื่อ calibrate

ADC2 กับ Wi-Fi ชนกัน

ขา ADC2 อ่านไม่ได้เมื่อ Wi-Fi ทำงาน → ใช้ขา ADC1 (GPIO32–39) สำหรับงาน AIoT

ต้องการความแม่นยำสูง

ใช้ ADC ภายนอก เช่น ADS1115 (16 บิต, I²C) แทน ADC ในชิป

อยากได้บิตเพิ่มฟรี ๆ

Oversampling + เฉลี่ย: สุ่มเพิ่ม 4 เท่า ได้ ≈ +1 บิต (SNR +6 dB) ถ้ามี noise พอเหมาะ

Choosing parameters

เลือก fs และจำนวนบิต ให้เหมาะกับงาน

งานความถี่สูงสุดของสัญญาณfs ที่นิยมใช้ความละเอียด
อุณหภูมิ / ความชื้นดินเปลี่ยนช้ามาก (< 1 Hz)1 Hz หรือช้ากว่า10–12 บิต
ECG หัวใจ~ 150 Hz250–500 Hz12–16 บิต
เสียงพูด / สั่งงานด้วยเสียง (TinyML)~ 8 kHz16 kHz16 บิต
โทรศัพท์~ 3.4 kHz8 kHz8 บิต (companded)
เพลงซีดี~ 20 kHz (หูมนุษย์)44.1 kHz16 บิต → SQNR ≈ 98 dB

ตัวเลขเป็นค่าที่ใช้กันทั่วไป (typical) ไม่ใช่ข้อกำหนดตายตัว · ในทางปฏิบัติเลือก fs สูงกว่า 2·fmax เพื่อเผื่อการ roll-off ของ anti-aliasing filter

Takeaways

สรุป 5 ข้อ ที่ต้องจำ

1ADC = สุ่ม → ปัด → เข้ารหัส

Sampling · Quantization · Encoding

2fs > 2·fmax

ไม่งั้นเกิด Aliasing กู้คืนไม่ได้ → ใช้ anti-aliasing filter

3LSB = Vref / 2N

บิตเยอะ = ละเอียด · error ไม่เกิน ±½ LSB · +1 บิต ≈ +6 dB

4เลือกชนิดตามงาน

Flash เร็ว · SAR สมดุล (ใน MCU) · ΣΔ แม่นยำ · Pipeline เร็วและละเอียด

5DAC: Vout = Vref·D / 2N

ไม่มี DAC ในชิป → PWM + low-pass filter · บน ESP32 ใช้ขา ADC1 เมื่อเปิด Wi-Fi และอย่าลืม calibrate
